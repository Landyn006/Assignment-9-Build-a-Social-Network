The social network program uses a graph data structure because it is the best way to represent friendships between people. Each person is represented as a node (vertex), and each friendship is represented as an edge connecting two people. Since friendships work both ways, the program uses an undirected graph. This allows each person to be connected to multiple other people without needing a specific order or hierarchy.

A graph is a better choice than a list or tree for this program. A list can store names, but it does not naturally show which people are friends with each other. A tree uses parent-child relationships, which would not work well for a social network because friendships can create cycles and multiple connections. A graph allows people to have many friendships and even share mutual friends.

The program uses a dictionary to store people by their names, which makes finding a specific person quick and efficient. The add_friendship method uses dictionary lookups to find both people and then adds each person to the other's friend list. This makes friendships work in both directions. However, each friendship must be stored twice, which uses additional memory. The print_network method also becomes slower as the network grows because it must visit every person and go through each person's friend list. Overall, this design is simple, organized, and effective for representing a social network.
